# Storyboard: structures, hooks, VO and the beat sheet

Portions adapted from Hyperframes (Apache-2.0, HeyGen) and brag (MIT).

A storyboard is a **proposal**. Open it with one line: "This film tells [audience] that [message]." Then show the beat sheet. Changing a beat here costs 30 seconds; changing it after the build costs an hour.

## 1. Extract the truth first

Write these six lines before choosing a structure. Every one must cite the claims ledger.

| Line | Question |
|---|---|
| Audience | Who is watching, and what do they already feel? |
| Tension | What pain or cost does the product's own site name? |
| Promise | The product's one-line promise, verbatim from its hero or tagline |
| Magic | The 2–3 moments where the real UI does something a viewer can see |
| Proof | Real logos, quotes, numbers or certifications **on the site**, or "demonstration only" |
| Offer | What the site actually offers: free trial, demo, pricing, download, URL |

## 2. Story structures (60–90 s)

Pick one and name it in the storyboard. Don't splice structures together. Times are output seconds.

### A. Problem → Magic → Proof (default, 75 s)

| Beat | Time | Content |
|---|---|---|
| Hook | 0–3 | Pain or outcome in ≤ 7 words, kinetic type |
| Tension | 3–10 | Agitate: the cost of the pain, in the site's words |
| Reveal | 10–16 | Name + promise, match cut onto the real hero |
| Magic 1 | 16–28 | Hero element 1: lift, expand, the inner part comes alive |
| Magic 2 | 28–40 | Hero element 2: camera push + callout overlay |
| Magic 3 | 40–55 | Hero element 3: the result state, the biggest payoff |
| Proof | 55–65 | Real proof element lifted, or the result held |
| Offer | 65–75 | URL + CTA lockup on the music's resolve |

### B. Cold open on the magic (60 s)

Start in the middle of the most impressive moment, then rewind ("Here's how.").

| Beat | Time | Content |
|---|---|---|
| Cold open | 0–4 | The result, already moving: lifted card at hero scale |
| Title | 4–8 | Name + promise; the card shrinks back into the page (inverse zoom) |
| How 1–3 | 8–44 | Three steps, one hero element each, ~12 s apiece |
| Proof | 44–52 | Proof or the result again, now understood |
| Offer | 52–60 | Lockup + URL |

### C. Before / After / Bridge (60–75 s)

| Beat | Time | Content |
|---|---|---|
| Before | 0–10 | The old way (glitch SFX, desaturated or dimmed backdrop), from the site's pain copy |
| After | 10–18 | The outcome state of the real product, clean and bright |
| Bridge | 18–60 | 2–3 magic beats: how it gets there |
| Offer | 60–75 | Lockup |

### D. Three superpowers (90 s)

A listicle with escalation. Each power is bigger than the last.

| Beat | Time | Content |
|---|---|---|
| Hook | 0–4 | "[Product] does three things [category] can't." (only if the site supports it) |
| Reveal | 4–12 | Name + promise |
| Power 1 | 12–32 | Smallest wow |
| Power 2 | 32–52 | Bigger |
| Power 3 | 52–72 | Biggest; it gets the strongest cue lock |
| Proof | 72–82 | |
| Offer | 82–90 | |

### E. A day with it (90 s)

A story arc: setup → tension → turn → resolution → offer. Use a role, not an invented person ("A two-person team. Monday morning."). Never invent a named customer.

### F. Myth vs reality (60 s)

| Beat | Time | Content |
|---|---|---|
| Myth | 0–5 | The common belief the site argues against |
| Reality | 5–12 | The product's counter-claim, verbatim |
| Evidence ×2 | 12–48 | Magic beats proving it |
| Offer | 48–60 | |

**Rhythm.** Name the rhythm before you build, for example `HOOK-tension-REVEAL-magic-magic-MAGIC-hold-proof-OFFER`. The slowest beat should be about 3× slower than the fastest. Place one deliberate held read before the biggest payoff.

## 3. Hook formulas (first 2–3 s)

Rules for every hook:

- Use outcome language: what the viewer gains, avoids or finally gets. No feature names, file names or "Introducing".
- Motion starts within 0.3 s and VO within 0.5 s. No logo first.
- At most 7 on-screen words. One idea.
- If the hook could open any competitor's ad, rewrite it with the product's own words.

| Formula | Template | Visual |
|---|---|---|
| Pain, named | "[Pain the site names]. Every [time unit]." | Kinetic type slam, glitch tick |
| The shortcut | "[Outcome] in [real time the site claims]." | Counter or progress racing to done |
| Contrast | "[Old way]. Or [new way]." | Split; the old half dims and blurs |
| Provocation | "You don't need [thing]. You need [outcome]." | Mask-rise words |
| Question | "What if [pain] just… [stopped]?" | Type-on with a caret |
| Cold open | No words. The magic, mid-motion. | Lifted card at hero scale |
| Stakes | "One [missed thing] costs [real cost from site]." | Number lands with an impact on the first strong cue |
| Direct address | "If you run [audience] — watch this." | Oversized cursor enters and clicks |

Numbers in hooks must carry stakes ("cut setup to minutes"), not inventory ("23 integrations"), and must exist in the ledger.

## 4. The middle: magic beats

Each magic beat has one hero element and three phases:

| Phase | Share | What happens | Typical move |
|---|---|---|---|
| Trigger | ~20% | The cause: a click, a scan starting, data arriving | Oversized cursor click, push-in |
| Transformation | ~50% | The real UI changes: bar fills, chip flips, rows sort | Lift & expand, inner-part animation |
| Result | ~30% | The new state, held and readable; VO lands the outcome | Held read, then put back or hand off |

Reveal each piece when the VO names it. Spread reveals across the back half of the beat. Never dump the whole frame in the first 25% and then freeze.

## 5. VO writing for ads

**Word budgets** (≈2.3 words/s, leaving room for music and holds):

| Runtime | Words | Hook | Each magic beat |
|---|---|---|---|
| 60 s | 120–140 | ≤ 8 | 18–25 |
| 75 s | 150–175 | ≤ 8 | 22–28 |
| 90 s | 180–210 | ≤ 10 | 25–32 |

Rules:

- Use short sentences, 3–9 words. Vary the length: two short ones, then one longer. End on the strong word.
- One idea per sentence and one sentence per on-screen change. Write in cues ("Connect your tools. Get your score. Fix what matters.") so each phrase can trigger a reveal.
- Use contractions and second person. Read it aloud; if it sounds like a brochure, rewrite it.
- Banned phrases: "streamline your workflow", "unlock the power", "seamless", "revolutionary", "Welcome to", "Introducing", "in today's fast-paced world".
- Quote the site's own phrasing for claims. Paraphrase only connective tissue.
- Leave silence. The script should feel shorter than the film. Two or three VO-free moments let music and SFX carry the magic.

**Show vs say:**

| The screen shows | The VO says |
|---|---|
| The mechanism (the click, the bar filling) | The outcome ("You're protected in minutes.") |
| The exact number (87) | The meaning ("a score you can actually improve") |
| The UI labels | Nothing. Never read on-screen text aloud word for word. |
| The URL lockup | The action, only if the site offers it ("Start free at example dot com.") |

**TTS mechanics:**

- Write what should be spoken: "forty-two percent", "A P I", "example dot com". The screen can show the exact figure while the voice rounds it.
- Use one `narration.json` segment per beat, anchored to its clip with `offsetMs`. Start 150–300 ms after the beat's first visible motion so the eye leads the ear.
- Set `project.json tts.instructions` as a director's note, for example: "Warm, confident commercial voice-over. Unhurried, smiling, clear diction. A slight lift on key phrases, a firm landing on the last word of each sentence. Never salesy or shouty." For a cinematic tone: "Low, intimate, deliberate. Short pause before the product name."
- Regenerate only changed segments, and keep the existing audio metadata.

## 6. Beat sheet template

Copy this into `demos/<name>/storyboard.md`:

```md
# <Product> — commercial (<runtime> s, <structure>)
This film tells <audience> that <message>.
Rhythm: <e.g. HOOK-tension-REVEAL-magic-magic-MAGIC-hold-proof-OFFER>
Mood: calm | bright | cinematic   Hero elements: <ref1>, <ref2>, <ref3>

| # | t (s) | Beat | Primitive | On screen (≤ 7 words/line) | VO | Move | Sound | Claim |
|---|---|---|---|---|---|---|---|---|
| 1 | 0.0–3.0 | Hook | scene hook.html | "<hook>" | "<hook VO>" | kinetic: focus-in word stagger | whoosh-soft @0.15, music in | C1 |
| 2 | 3.0–10.0 | Tension | rec clip a, backdrop dim .5 | — | "<…>" | push-in 1.3, easeMs 1200 | glitch @4.1 | C2 |
| 3 | 10.0–16.0 | Reveal | scene title.html → rec b | "<Name>" + "<promise>" | "<…>" | mask rise → match cut | impact @ strongCue 10.9 | C3 |
| 4 | 16.0–28.0 | Magic 1 | rec c + overlay lift-score | — | "<…>" | lift & expand, dial counts | whoosh @ pick-up, chime @ land | C4 |
| … | | | | | | | | |
| 8 | 65.0–75.0 | Offer | scene outro.html | "<URL>" | "<CTA>" | lockup, hold 2.5 s | lands on resolveMs | C9 |
```

**Claims ledger:**

```md
| ID | Claim as used | Verbatim source text | URL | Used in beat |
|---|---|---|---|---|
| C1 | "<on-screen or VO wording>" | "<exact site text>" | https://… | 1 |
```

A beat with no claim ID asserts nothing about the product (pure tone or framing). That is fine. A beat that asserts something without an ID is a bug.

## 7. Storyboard self-check

- [ ] One structure named. Rhythm declared. Duration 60–90 s, and the beat durations add up.
- [ ] Hook in outcome language, ≤ 7 words, motion by 0.3 s. Value claim by beat 2.
- [ ] 3–5 hero elements, each real and liftable, each owning one beat.
- [ ] Each beat names one primitive and one named move from `motion-vocabulary.md`.
- [ ] VO within the word budget, written in cues, numbers spelled out.
- [ ] Every on-screen word fits its reading floor in the beat's duration.
- [ ] Every assertion has a claims-ledger row with a URL. Proof is real or "demonstration only".
- [ ] Offer and URL exist on the site. The final lockup holds ≥ 2.5 s.
